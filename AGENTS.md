# AGENTS.md

## Project

`nyx` — a fully local ONNX inference tool, no cloud. Bun monorepo. `README.md` / `README.zh_CN.md` cover model setup and CLI usage; trust the source tree when they drift.

## Commands

Run everything with bun, never npm. Versions are pinned via the workspace `catalog` in the root `package.json` (`bunfig.toml` `exact = true`) — add new deps as `catalog:` entries, never inline versions.

```bash
bun install
bun run typecheck             # tsc --noEmit for every @nyx/* package
bun run dev                   # run the CLI directly (root script)
bun --cwd apps/coding-agent run src/index.ts --help
bun --cwd packages/server run build   # emit dist/server.cjs for the desktop app
```

- Focused check after touching one package: `bun --cwd packages/<pkg> run typecheck`.
- `build` == `typecheck` (`tsc --noEmit`) in every package except `@nyx/server`, whose `build` also runs `vite build` to emit `dist/server.cjs`. No other package emits `dist/`.
- Root `lint`/`test` scripts exist but NO package defines a `lint` or `test` script, so they fail with "No packages matched the filter". Verification is `bun run typecheck`.
- `tsc` lives only in `node_modules/.bin`; use the bun-script forms above, never bare `tsc`. `@nyx/desktop` typecheck runs two passes (`tsconfig.json` + `tsconfig.node.json` for main/preload).
- All packages are `"type": "module"`; sources import each other with explicit `.ts` extensions (e.g. `../runtime.ts`) — required for bun's TS resolution here, keep it.

## Architecture

Dependency direction: `@nyx/config` ← {`@nyx/llm`, `@nyx/agent`} ← `@nyx/server` ← `apps/*` (all `workspace:*`; `@nyx/llm` and `@nyx/agent` are siblings).

- `packages/config` — `~/.nyx` paths (`getModelsDir`, overridable via `NYX_MODELS_DIR`), the model registry at `~/.nyx/models.json` as `{ provider: { <org>: { models: { <name>: ModelInfo } } } }` (`read()`/`write()` with defu deep-merge), and user settings at `~/.nyx/settings.json` (`getSettings`/`setSettings`: `hubBaseUrl` plus `agent` = `{ provider, model, baseUrl, apiKey, headers, systemPrompt, maxSteps }`, all optional). `getAgentSettings()` merges `settings.agent` with `NYX_AGENT_{PROVIDER,MODEL,BASE_URL,API_KEY,HEADERS}` env overrides (env wins per field; `HEADERS` is a JSON object). `ModelInfo.task`/`dtype` use transformers.js `PipelineType`/`DataType` directly — no zod.
- `packages/llm` — ONNX runtime + tasks. `src/runtime.ts` is the single shared loader (`configureEnv` sets `env.cacheDir` + remote/local download; `loadPipeline` memoizes per `task:dtype:model`). Download host precedence: `options.env.remoteHost` > `HF_ENDPOINT` env (e.g. `https://hf-mirror.com`) > `settings.hubBaseUrl` (skipped when it equals `DEFAULT_HUB_URL`). `src/models.ts` is the registry (`list` filters to entries still on disk; `pull` records into the config; optional `dtype` arg is an advanced override — omit it and transformers.js picks the device default; `find` reads a record by id). `pull()` takes an optional `AbortSignal`: since transformers.js downloads can't be interrupted, the signal is bridged through the progress callback, which throws `PullAbortedError` per chunk once aborted (wrapping the callback also forces the streaming download path — no callback means the arrayBuffer fast path). An abort landing after the last chunk prevents registration. `src/tasks/*` are provider classes, one per task: `OnnxTextGenerationProvider.stream()` (TextStreamer) and `OnnxImageToImageProvider.generate()`; both implement the shared `LLMProvider` surface (`id`/`model`/`task`) and default their dtype to the value recorded at pull time (`options.dtype ?? find(model)?.dtype`) so inference reuses the cached variant. Types come from `@huggingface/transformers`, not `@nyx/config`. `types.ts` owns the wire message type `LLMMessage { role: user|assistant|system; content: string }` — the single transcript shape used by every caller (no separate content-block model today).
- `packages/agent` — the remote "master brain" agent core, built on the official `ai` SDK (Vercel AI SDK v7). No onnx/transformers dependency. `src/agent.ts` exposes `streamAgent(options): AsyncIterable<AgentEvent>` (a thin `streamText` wrapper) and `toAiTools` maps a declarative `AgentToolSet` to AI SDK tools + a per-tool `toolApproval` policy (`"always"` → `"user-approval"`, else `not-applicable`). `src/providers.ts` is the provider registry (`openai-compatible` via `createOpenAICompatible`, `anthropic` via `createAnthropic`); add a provider by extending one `switch`. `src/types.ts` owns `AgentTool` (`name`/`description`/`inputSchema`/`approval`/`execute`), `AgentEvent` (`text-delta`/`tool-call`/`tool-result`/`tool-error`/`tool-denied`/`approval-request`/`finish`/`error`), and `AgentRunOptions`. `model` accepts either an `AgentModelConfig` (resolved through the registry) or a pre-built AI SDK `LanguageModel` (used for tests / custom providers). The tool set is heterogeneous, so `AgentToolSet = AgentTool<any, any>[]` erases per-tool input types at the collection boundary (mirrors AI SDK's `ToolSet`). Tools own their own `execute`; the transcript type is AI SDK `ModelMessage[]` (re-exported).
- `packages/server` — Hono inference service under `/v1` (models / text-generation / image-to-image / agent). Spawned by the desktop app as a plain process: onnxruntime-node crashes inside Electron's full Node runtime (SIGTRAP), so inference lives in a child spawned with `ELECTRON_RUN_AS_NODE=1` (the app's own Electron binary acting as plain Node — no system `node` needed). Standalone entry `src/server.ts` reads `NYX_SERVER_TOKEN` (required — exits without it), `NYX_SERVER_PORT` (default 0 = ephemeral), `NYX_SERVER_HOST` (default 127.0.0.1), prints `nyx-server-ready <url>` on stdout. Bearer-token auth middleware when a token is set. Layout mirrors the resource URLs: one `routes/<resource>.ts` paired with one `services/<resource>.ts` (`models`, `text-generation`, `image-to-image`, `agent`), a sub-app factory per resource injecting only its own service, so routes hold no state. `services/models.ts` (`ModelsService`) additionally tracks in-flight pulls per model id (`isPulling`/`beginPull`/`cancelPull`/`endPull`) behind `POST /pull` and `POST /pull/cancel`. `services/agent.ts` (`AgentService`) resolves the brain from `getAgentSettings()` and runs `streamAgent` with `lib/agent-tools.ts`; `POST /v1/agent` streams the `AgentEvent`s as SSE (event name = `event.type`) and aborts via the request signal. Shared low-level helpers (not a resource) live in `lib/` — `lib/provider-cache.ts` is the one provider cache shared by the task services and the model service so removing a model also evicts its loaded weights; `lib/agent-tools.ts` (`createAgentTools({ workspaceDir })`) is the six coding tools (`read_file`/`grep`/`glob` auto-run; `write_file`/`edit_file`/`bash` require approval). All file/bash tools are confined to `workspaceDir` (path-escape check); `bash` runs with `cwd=workspaceDir`, a timeout, and an output cap. `app.ts` exposes `createApp({ token?, services? })` (`Services` = one instance per resource) and wires the `/v1` group (auth + `/health`). Text generation is stateless multi-turn: each request carries the full `messages[]` transcript (`LLMMessage` from `@nyx/llm`) and is forwarded straight to the text provider, which applies the model's chat template internally. Model types are not redefined here — `ModelInfo` is `@nyx/config`'s and `LLMTask` is `@nyx/llm`'s.
- `apps/coding-agent` — yargs CLI: bare `nyx` (`$0`) is the **master-brain agent TUI** (remote model + local coding tools; `--cwd` workspace, `--model`/`--provider`/`--base-url` overrides); subcommands `text-generation`, `image-to-image`, and `model` (`pull <model> --task`, `list`/`ls`, `remove <model>`). Modules in `src/cli/commands/`; `src/cli/utils/cmd.ts` is the yargs typing helper. yargs is `.strict()`, so unknown flags reject. `src/tui.ts` holds the whole TUI: a private `ChatTui` shell (transcript view, editor, slash commands, Ctrl+C/D handling) plus `runAgentTui`, which streams assistant text, tool cards, and inline y/n approval through it. The agent command starts an ephemeral loopback server (`start()` from `@nyx/server`), POSTs the transcript to `/v1/agent` (SSE, no token), and stops the server on exit — the loop lives server-side. Local models are one-shot only (`nyx text-generation`), driven directly by `OnnxTextGenerationProvider`.
- `apps/desktop` — Electron shell (forge + vite + React), single instance (shared model cache). Package.json declares `@nyx/{config,llm,server}`, but `src/` uses `@nyx/config` at runtime (settings/paths) and only *types* from `@nyx/llm` + `@nyx/server/types` — main never pulls in onnxruntime/transformers; inference runs solely in the spawned server child, reached via `src/main/server/index.ts` (NyxServer) + `client.ts` (typed SSE/HTTP client). Main is a stateless proxy: `TextGenerationService`/`ImageToImageService` (one per task) hold no model/busy state — model selection lives in the renderer's `useModelsStore`, and each call passes its `modelId` + full transcript (`LLMMessage[]`) through IPC → main → server. Model pulls surface in `useModelsStore` as a `pulling` map (per-model progress); a cancel routes IPC → `POST /v1/models/pull/cancel` → the server aborts and cleans partial files. Streaming events come back as `TextGenerationEvent` (mirrors the server SSE wire: `delta`/`end`/`error`). Renderer uses path aliases `#components`/`#lib`/`#hooks` (from package.json `imports`) with shadcn/base-ui components in `src/renderer/src/components/ui/` (see `components.json`, `.claude/skills/shadcn/`). The agent UI/ IPC is not wired here yet (phase 2).

## Naming & Layout Rules

- Name files and classes by the resource/function they serve, not by a role. In `packages/server`: a `routes/<resource>.ts` is paired 1:1 with a `services/<resource>.ts`, and the resource name matches the URL it mounts under (`models`, `text-generation`, `image-to-image`, `agent`). Avoid catch-all names like `inference`/`service`/`model-store` when the resource already has a name — prefer `ModelsService`, `TextGenerationService`, `ImageToImageService`, `AgentService`.
- Layer boundaries map to folders. `routes/` = HTTP sub-apps (no state), `services/` = one business class per route with the same name, `lib/` = shared low-level helpers that are not themselves a resource (e.g. `provider-cache.ts`, `agent-tools.ts`), `middleware/`, `shared/` = cross-layer wire types. When a class is shared only as infrastructure and not a business service, put it in `lib/`, not `services/`.
- Keep each service single-purpose. If one class starts mixing unrelated concerns (e.g. both running inference tasks and managing the model cache), split it so each route injects only the slice it needs.

## Gotchas

- Models cache in `~/.nyx/models/` and download lazily on first use (`allowRemoteModels`/`allowLocalModels` default on); pre-download with `nyx model pull <model> --task <text-generation|image-to-image>` (advanced `--dtype` pins a variant; omit to let transformers.js pick the device default — fp32 on Node/CPU). To download via a mirror, set `HF_ENDPOINT` (e.g. `https://hf-mirror.com`) — `configureEnv` maps it to `env.remoteHost`, and the desktop app inherits it into the spawned server child via `...process.env`. Code changes never re-trigger downloads; a missing model surfaces as a pipeline load error.
- Task commands (`text-generation`, `image-to-image`) require `--model`; `nyx model pull/remove` take a positional `<model>`. Bare `nyx` (agent TUI) needs a configured remote brain instead (see next bullet) and a TTY (`isatty` guard rejects non-interactive stdin). First load of a large model is slow — pipelines/providers are memoized per process.
- The agent brain is a **remote** model (departs from "fully local"): configure `agent.{provider,model,baseUrl,apiKey,headers}` in `~/.nyx/settings.json` or the `NYX_AGENT_*` env vars; `provider` is `openai-compatible` (needs `baseUrl`) or `anthropic`. Some gateways require extra request headers (e.g. opencode zen insists on `x-opencode-session`) — set them via `agent.headers`. The brain's tools are local coding tools confined to `--cwd` (default cwd). Approval is a **two-call, stateless flow**: AI SDK v7 does not pause — `streamText` finishes with `tool-approval-request` parts, so `streamAgent` returns the assistant/tool messages in its `finish` event and the caller re-sends the transcript with a `tool-approval-response` in a `tool` message (see `packages/agent/src/types.ts`). In AI SDK v7 use `stream` (not `fullStream`) and `toolApproval` (not `needsApproval`).
- `packages/server/vite.config.ts` externalizes only `onnxruntime-node`/`onnxruntime-common`/`sharp`/`@huggingface/transformers` + `node:` — everything else (including `ai`, the `@ai-sdk/*` providers, `zod`, and `@nyx/agent`) is bundled into `dist/server.cjs`, so adding agent deps needs no forge runtime-copy changes. Only externalized native/runtime deps must be added to `apps/desktop/forge.config.ts`'s closure copy.
- Desktop dev needs the server bundle first: `bun --cwd packages/server run build`; NyxServer resolves `packages/server/dist/server.cjs` (dev) or a packaged `Resources/runtime/server.cjs`. Packaging (`bun --cwd apps/desktop run make`) stages that runtime via the forge `packageAfterCopy` hook: the asar ships only `.vite` + `package.json` (all JS deps are Vite-bundled; bun's `node_modules` are store symlinks asar cannot follow), and the server's dereferenced runtime closure (`@huggingface/transformers`, `onnxruntime-node/-common`, `sharp` + `@img/*`) is copied to `Resources/runtime/node_modules` so the plain-node child resolves it.
- The server must call `serve({ ..., overrideGlobalObjects: false })` (`packages/server/src/index.ts`). `@hono/node-server` otherwise replaces the global `Response`/`Request` with its own classes, which makes transformers.js `response instanceof Response` fail and silently skips writing downloads to the FS cache (0-byte files, then `Unable to get model file path or buffer.`). Do not drop this option.
- `packageManager` is pinned (`bun@1.3.14`); root `engines.node >= 20`.
