# AGENTS.md

## Project

`nyx` — a desktop agent with hybrid cloud + local ONNX inference. Bun monorepo. `README.md` / `README.zh_CN.md` cover model setup and CLI usage; trust the source tree when they drift.

## Commands

Run everything with bun, never npm. Versions are pinned via the workspace `catalog` in the root `package.json` (`bunfig.toml` `exact = true`) — add new deps as `catalog:` entries, never inline versions.

```bash
bun install
bun run typecheck             # tsc --noEmit for every @nyx/* package
bun run dev                   # run the agent CLI directly (root script)
bun run --cwd apps/coding-agent src/index.ts --help
bun run --cwd packages/server build   # emit dist/server.cjs for the desktop app
bun run dev:desktop           # start the Electron app (build the server bundle first)
bun run --cwd packages/server dev     # standalone server (requires NYX_SERVER_TOKEN)
```

- Focused check after touching one package: `bun run --cwd packages/<pkg> typecheck`.
- **`bun --cwd <dir> run <script>` is broken** (prints bun's usage and exits) — put `run` before `--cwd`: `bun run --cwd <dir> <script>`. The root `dev`/`dev:desktop` scripts use the working forms already.
- `build` is `tsc --noEmit` for `@nyx/{config,llm,agent}` and `apps/coding-agent`; `@nyx/server`'s `build` adds `vite build` (the only package that emits `dist/server.cjs`); `@nyx/desktop` has no `build` script (use `typecheck`, or `make` to package).
- No tests exist anywhere: root `lint`/`test` scripts exist but NO package defines a `lint` or `test` script, so they fail with "No packages matched the filter". Verification is `bun run typecheck` (build the server bundle too after `@nyx/{config,llm,agent,server}` changes — desktop dev loads the stale `dist/`).
- `dist/` and `.vite/` are gitignored; never expect to commit build output.
- `tsc` lives only in `node_modules/.bin`; use the bun-script forms above, never bare `tsc`. `@nyx/desktop` typecheck runs two passes (`tsconfig.json` + `tsconfig.node.json` for main/preload).
- All packages are `"type": "module"`; sources import each other with explicit `.ts` extensions (e.g. `../runtime.ts`) — required for bun's TS resolution here, keep it. `@ai-sdk/react` pins an exact `ai` version (4.0.102 → ai 7.0.99), which is why both are catalog entries.

## Architecture

Dependency direction: `@nyx/config` ← {`@nyx/llm`, `@nyx/agent`} ← `@nyx/server` ← `apps/*` (all `workspace:*`; `@nyx/llm` and `@nyx/agent` are siblings).

- `packages/config` — `~/.nyx` paths (`getModelsDir`, overridable via `NYX_MODELS_DIR`), the model registry at `~/.nyx/models.json` as `{ provider: { <org>: { models: { <name>: ModelInfo } } } }` (`read()`/`write()` with defu deep-merge), and user settings at `~/.nyx/settings.json` (`getSettings`/`setSettings`: `hubBaseUrl` plus `agent` = `{ model, provider, tools, workspaceDir, systemPrompt, maxSteps }`). `agent.model` is a `<providerId>/<modelId>` ref into `agent.provider`, a map of `{ npm, name?, options, limit? }` (opencode-style) where `npm` is the AI SDK package and `options` holds `baseURL`/`apiKey`/`headers`. `agent.tools.localModels` (default false) exposes installed ONNX models to the agent as tools. `getAgentSettings()` applies env overrides: `NYX_AGENT_MODEL` replaces the ref, `NYX_AGENT_{API_KEY,BASE_URL,HEADERS}` override the active provider's `options` (`HEADERS` is a JSON object), and `NYX_AGENT_LOCAL_MODELS` toggles `tools.localModels`. `ModelInfo.task`/`dtype` use transformers.js `PipelineType`/`DataType` directly — no zod.
- `packages/llm` — ONNX runtime + tasks. `src/runtime.ts` is the single shared loader (`configureEnv` sets `env.cacheDir` + remote/local download; `loadPipeline` memoizes per `task:dtype:model`). Download host precedence: `options.env.remoteHost` > `HF_ENDPOINT` env (e.g. `https://hf-mirror.com`) > `settings.hubBaseUrl` (skipped when it equals `DEFAULT_HUB_URL`). `src/models.ts` is the registry (`list` filters to entries still on disk; `pull` records into the config; optional `dtype` arg is an advanced override — omit it and transformers.js picks the device default; `find` reads a record by id). `pull()` takes an optional `AbortSignal`: since transformers.js downloads can't be interrupted, the signal is bridged through the progress callback, which throws `PullAbortedError` per chunk once aborted (wrapping the callback also forces the streaming download path — no callback means the arrayBuffer fast path). An abort landing after the last chunk prevents registration. `src/tasks/*` are provider classes, one per task: `OnnxTextGenerationProvider.stream()` (TextStreamer), `OnnxImageToImageProvider.generate()`, and `OnnxTextToAudioProvider.generate()` (returns a transformers.js `RawAudio`; optional `speaker`/`speed`/`numInferenceSteps` pass-through for models that need them); each implements the shared `LLMProvider` surface (`id`/`model`/`task`) and defaults its dtype to the value recorded at pull time (`options.dtype ?? find(model)?.dtype`) so inference reuses the cached variant. `LLM_TASKS` in `types.ts` is the one source of truth for valid task ids — server-side pull validation is derived from it. Types come from `@huggingface/transformers`, not `@nyx/config`. `types.ts` owns the wire message type `LLMMessage { role: user|assistant|system; content: string }` — the single transcript shape used by every caller (no separate content-block model today).
- `packages/agent` — the remote "master brain" agent core, built on the official `ai` SDK (Vercel AI SDK v7). No onnx/transformers dependency. `src/agent.ts` exposes `streamAgent(options): Promise<Response>`: it builds a `ToolLoopAgent` (the model + `instructions` + tools + `toolApproval`, `stopWhen: isStepCount(maxSteps)` only when set) and returns the AI SDK **UI message stream** via the SDK's `createAgentUIStreamResponse` (with `generateMessageId`, so messages always carry ids); the agent owns the tool loop (default 20 steps) and the caller drives the stream with `useChat` / `readUIMessageStream` — there is no bespoke event union. `toAiTools` maps a declarative `AgentToolSet` to AI SDK tools + a per-tool `toolApproval` policy (`"always"` → `"user-approval"`, else `not-applicable`). `src/providers.ts` holds the registry: `resolveModelConfig(settings)` turns `agent.{model,provider}` into a `ResolvedAgentModel` (`npm`/`model`/`apiKey`/`baseURL`/`headers`/`maxOutputTokens`, validating the ref + required options), and `resolveModel(config)` selects the provider by its AI SDK npm package (`@ai-sdk/openai-compatible` → `createOpenAICompatible`, `@ai-sdk/anthropic` → `createAnthropic`) — add a package by extending one `switch`. `src/types.ts` owns `AgentTool` (`name`/`description`/`inputSchema`/`approval`/`execute`) and `AgentRunOptions`, and re-exports the AI SDK UI-message types (`UIMessage`/`UIMessageChunk`). `model` accepts either a `ResolvedAgentModel` or a pre-built AI SDK `LanguageModel`; the provider's `limit.output` becomes `maxOutputTokens`. The tool set is heterogeneous, so `AgentToolSet = AgentTool<any, any>[]` erases per-tool input types at the collection boundary (mirrors AI SDK's `ToolSet`) and `InferAgentUIMessage` cannot statically type it — clients handle tool parts dynamically (`isToolUIPart`/`getToolName`). Tools own their own `execute`; the transcript is AI SDK `UIMessage[]`.
- `packages/server` — Hono inference service under `/v1` (models / tasks/text-generation / tasks/image-to-image / tasks/text-to-audio / agent). Spawned by the desktop app as a plain process: onnxruntime-node crashes inside Electron's full Node runtime (SIGTRAP), so inference lives in a child spawned with `ELECTRON_RUN_AS_NODE=1` (the app's own Electron binary acting as plain Node — no system `node` needed). Standalone entry `src/server.ts` reads `NYX_SERVER_TOKEN` (required — exits without it), `NYX_SERVER_PORT` (default 0 = ephemeral), `NYX_SERVER_HOST` (default 127.0.0.1), prints `nyx-server-ready <url>` on stdout. Bearer-token auth middleware when a token is set. Layout mirrors the resource URLs: one `routes/<resource>.ts` paired with its service — the inference-task services live under `services/tasks/<resource>.ts` (`text-generation`, `image-to-image`, `text-to-audio`), while `services/models.ts` and `services/agent.ts` are top-level. Routes mount under `/v1/models`, `/v1/tasks/<resource>`, and `/v1/agent`, each a sub-app factory injecting only its own service, so routes hold no state. `services/models.ts` (`ModelsService`) additionally tracks in-flight pulls per model id (`isPulling`/`beginPull`/`cancelPull`/`endPull`) behind `POST /pull` and `POST /pull/cancel`. `services/agent.ts` (`AgentService`) resolves the brain from `getAgentSettings()` and runs `streamAgent` with `lib/agent-tools.ts` (the coding tools) plus, when `agent.tools.localModels` is on, `lib/model-tools.ts` (the installed local ONNX models as tools); `POST /v1/agent` returns the AI SDK UI message stream (SSE) and aborts via the request signal. `/v1/tasks/text-generation` emits that same UI-message protocol via `createUIMessageStream`, so both endpoints are consumed by the same client transport; `/v1/tasks/image-to-image` and `/v1/tasks/text-to-audio` return raw bytes (PNG / WAV) with shape/rate metadata in headers. Shared low-level helpers (not a resource) live in `lib/` — `lib/provider-cache.ts` is the one provider cache shared by the task services, the model service, and `AgentService` (so removing a model also evicts its loaded weights and agent tools reuse them); `lib/workspace.ts` holds the path-confinement helpers (`workspacePath`/`realpathNearest`); `lib/agent-tools.ts` (`createAgentTools({ workspaceDir })`) is the six coding tools (`read_file`/`grep`/`glob` auto-run; `write_file`/`edit_file`/`bash` require approval); `lib/model-tools.ts` (`createModelTools({ cache, workspaceDir })`) adds `local_text_generation` (auto-run), `local_image_to_image` (approval; writes PNG into the workspace), and `local_text_to_audio` (approval; writes WAV into the workspace), each offering the installed models of its task. All file/bash tools are confined to `workspaceDir` (path-escape check); `bash` runs with `cwd=workspaceDir`, a timeout, and an output cap. `app.ts` exposes `createApp({ token?, services? })` (`ServerServices` = one instance per resource) and wires the `/v1` group (auth + `/health`). Model types are not redefined here — `ModelInfo` is `@nyx/config`'s and `LLMTask` is `@nyx/llm`'s.
- `apps/coding-agent` — yargs CLI: bare `nyx` (`$0`) is the **master-brain agent TUI** (remote model + local coding tools; `--cwd` workspace, `--model`/`--base-url` overrides); subcommands `text-generation`, `image-to-image`, `text-to-audio`, and `model` (`pull <model> --task`, `list`/`ls`, `remove <model>`). Modules in `src/cli/commands/`; `src/cli/utils/cmd.ts` is the yargs typing helper. yargs is `.strict()`, so unknown flags reject. The agent TUI is `@ai-sdk/tui`'s `runAgentTUI` (streaming output, tool cards, reasoning, inline y/n approvals); the command starts an ephemeral loopback server (`start()` from `@nyx/server`), points a `DefaultChatTransport` at `${server.url}/v1/agent` (body: `workspaceDir`/`model`/`baseURL`, no token), and stops the server on exit — the loop lives server-side. There is no custom TUI/theme/autocomplete code (the old `pi-tui`-based `src/tui.ts`, `src/components/`, `src/theme/`, `src/autocomplete.ts` were removed). Local ONNX models are used one-shot via `nyx text-generation`/`nyx image-to-image`/`nyx text-to-audio` (driven directly by the `Onnx*Provider` classes), or, when `agent.tools.localModels` is on, as agent tools inside the agent TUI (loop-side, via `@nyx/server`).
- `apps/desktop` — Electron shell (forge + vite + React), single instance (shared model cache). Package.json declares `@nyx/{config,llm,server}`, but `src/` uses `@nyx/config` at runtime (settings/paths) and only *types* from `@nyx/llm` + `@nyx/server/types` — main never pulls in onnxruntime/transformers; inference runs solely in the spawned server child, reached via `src/main/server/index.ts` (NyxServerProcess) + `client.ts` (typed SSE/HTTP client). The renderer also uses `ai` + `@ai-sdk/react` (UI-message chat/`useChat`) and `streamdown` (markdown), all Vite-bundled. Main is a stateless proxy: `ImageToImageService`/`TextToAudioService` hold no state, and `ChatStreamService` (one generic streamer for both chat endpoints) just relays chunks — model selection lives in the renderer's `useModelsStore`, and each call passes its body (`messages` + `model`/`workspaceDir`) through IPC → main → server. Model pulls surface in `useModelsStore` as a `pulling` map (per-model progress); a cancel routes IPC → `POST /v1/models/pull/cancel` → the server aborts and cleans partial files. The renderer drives both chats with `@ai-sdk/react`'s `useChat` over a shared `ai` `Chat` instance per endpoint (`lib/chat.ts`): a custom `ChatTransport` bridges to `IPC.chat.*` (renderer-generated `streamId`, `chunk`/`end`/`error` events) and reassembles a `ReadableStream<UIMessageChunk>`. The **Agent** page (`pages/AgentPage.tsx`, the default route) is the master-brain chat: `store/agent.ts` keeps only the read-only settings (brain label / workspace), the transcript is `useChat`'s `UIMessage[]`, and tool approvals are inline `components/agent/ApprovalCard.tsx` prompts that call `addToolApprovalResponse` (auto-resubmitted via `lastAssistantMessageIsCompleteWithApprovalResponses`). The workspace the coding tools are confined to comes from `agent.workspaceDir` (picked via `dialog.selectDirectory`); the master brain is shown read-only. Shared chat pieces live in `components/chat/` (`ChatComposer`, `MarkdownText` — wraps `streamdown` (with the `@streamdown/code` + `@streamdown/cjk` plugins) for streaming-safe markdown and a `caret`/`isAnimating` streaming indicator, `StreamingMarker`); the Agent page renders text, reasoning (muted), and tool parts; the text-generation page renders text only; the image-to-image and text-to-audio pages are one-shot task pages (pick a model, run, preview the result). Renderer uses path aliases `#components`/`#lib`/`#hooks` (from package.json `imports`) with shadcn/base-ui components in `src/renderer/src/components/ui/` (see `components.json`, `.claude/skills/shadcn/`).

## Naming & Layout Rules

- Name files and classes by the resource/function they serve, not by a role. In `packages/server`: a `routes/<resource>.ts` is paired 1:1 with its service, and the resource name matches the URL it mounts under (`models`, `tasks/text-generation`, `tasks/image-to-image`, `tasks/text-to-audio`, `agent`); the inference-task services live under `services/tasks/`, the rest directly under `services/`. Avoid catch-all names like `inference`/`service`/`model-store` when the resource already has a name — prefer `ModelsService`, `TextGenerationService`, `ImageToImageService`, `TextToAudioService`, `AgentService`.
- Layer boundaries map to folders. `routes/` = HTTP sub-apps (no state), `services/` = one business class per route with the same name (task services grouped in `services/tasks/`), `lib/` = shared low-level helpers that are not themselves a resource (e.g. `provider-cache.ts`, `agent-tools.ts`, `model-tools.ts`, `workspace.ts`), `middleware/`, `shared/` = cross-layer wire types. When a class is shared only as infrastructure and not a business service, put it in `lib/`, not `services/`.
- Keep each service single-purpose. If one class starts mixing unrelated concerns (e.g. both running inference tasks and managing the model cache), split it so each route injects only the slice it needs.

## Gotchas

- **Adding a new local task touches a fixed set of hardcoded lists.** Add the id to `LLM_TASKS` (`packages/llm/src/types.ts`) — server-side pull validation derives from it — then update the spots that still hardcode the set: CLI `model/pull.ts` `TASK_CHOICES` + its usage string, desktop `ModelsPage.tsx` `TASK_OPTIONS`/`TASK_LABEL`/the `onValueChange` guard, `Sidebar.tsx` (`ViewId`/`NAV`), and `App.tsx` (`PAGE_TITLES` + route). Then add the provider (`packages/llm/src/tasks/<task>.ts`), service (`packages/server/src/services/tasks/<task>.ts`), route, `app.ts` wiring, a CLI command, desktop IPC (`shared/ipc.ts` + `shared/types.ts` `NyxApi` + `main/ipc.ts` + `main/index.ts` + `preload/index.ts`), the server client method, and (optionally) a `model-tools.ts` agent tool.
- Models cache in `~/.nyx/models/` and download lazily on first use (`allowRemoteModels`/`allowLocalModels` default on); pre-download with `nyx model pull <model> --task <text-generation|image-to-image|text-to-audio>` (advanced `--dtype` pins a variant; omit to let transformers.js pick the device default — fp32 on Node/CPU). To download via a mirror, set `HF_ENDPOINT` (e.g. `https://hf-mirror.com`) — `configureEnv` maps it to `env.remoteHost`, and the desktop app inherits it into the spawned server child via `...process.env`. Code changes never re-trigger downloads; a missing model surfaces as a pipeline load error.
- Task commands (`text-generation`, `image-to-image`, `text-to-audio`) require `--model`; `nyx model pull/remove` take a positional `<model>`. Bare `nyx` (agent TUI) needs a configured remote brain instead (see next bullet) and a TTY (`isatty` guard rejects non-interactive stdin). First load of a large model is slow — pipelines/providers are memoized per process.
- The agent brain is a **remote** model (departs from "fully local"): configure `agent.model` (a `<providerId>/<modelId>` ref) and `agent.provider.<id>` (`{ npm, options: { baseURL, apiKey, headers }, limit }`) in `~/.nyx/settings.json`, or override with `NYX_AGENT_MODEL` / `NYX_AGENT_{API_KEY,BASE_URL,HEADERS}`. `npm` is `@ai-sdk/openai-compatible` or `@ai-sdk/anthropic`. Some gateways require extra request headers (e.g. opencode zen insists on `x-opencode-session`) — set them via the provider's `options.headers`. The brain's tools are local coding tools confined to `--cwd` (default cwd); with `agent.tools.localModels` on, the installed local ONNX models are also exposed as `local_text_generation` (auto-run), `local_image_to_image` (approval; writes a PNG), and `local_text_to_audio` (approval; writes a WAV) — their output is sent back to the remote brain. Approval is a **two-call, stateless flow**, and the AI SDK UI message stream carries it natively: the agent emits a `tool-approval-request` part and stops, the client answers with `addToolApprovalResponse` (desktop) or by flipping the part to `approval-responded` (CLI), and the whole `UIMessage[]` transcript is re-sent. In AI SDK v7 the policy is `toolApproval` (not `needsApproval`).
- `packages/server/vite.config.ts` externalizes only `onnxruntime-node`/`onnxruntime-common`/`sharp`/`@huggingface/transformers` + `node:` — everything else (including `ai`, the `@ai-sdk/*` providers, `zod`, and `@nyx/agent`) is bundled into `dist/server.cjs`, so adding agent deps needs no forge runtime-copy changes. Only externalized native/runtime deps must be added to `apps/desktop/forge.config.ts`'s closure copy.
- Desktop dev needs the server bundle first: `bun run --cwd packages/server build`; NyxServerProcess resolves `packages/server/dist/server.cjs` (dev) or a packaged `Resources/runtime/server.cjs`. Packaging (`bun run --cwd apps/desktop make`) stages that runtime via the forge `packageAfterCopy` hook: the asar ships only `.vite` + `package.json` (all JS deps are Vite-bundled; bun's `node_modules` are store symlinks asar cannot follow), and the server's dereferenced runtime closure (`@huggingface/transformers`, `onnxruntime-node/-common`, `sharp` + `@img/*`) is copied to `Resources/runtime/node_modules` so the plain-node child resolves it.
- The server must call `serve({ ..., overrideGlobalObjects: false })` (`packages/server/src/index.ts`). `@hono/node-server` otherwise replaces the global `Response`/`Request` with its own classes, which makes transformers.js `response instanceof Response` fail and silently skips writing downloads to the FS cache (0-byte files, then `Unable to get model file path or buffer.`). Do not drop this option.
- `packageManager` is pinned (`bun@1.3.14`); root `engines.node >= 22` (the CLI's `@ai-sdk/tui` requires Node 22, though everything runs under bun).
- The desktop UI is shadcn **Base UI** (`components.json` `style: "base-nova"`, `@base-ui/react`, aliases `#components`/`#lib` from package.json `imports`). Do NOT add `ai-elements` (Radix/Next-oriented): its CLI ignores the `#` aliases (writes to `src/components`) and would overwrite the Base UI `ui/` primitives. Use the project's native chat primitives instead — `components/ui/` ships `message-scroller` (`MessageScroller*`), `message` (`Message*`), `bubble`, `marker` (see `.agents/skills/shadcn/rules/chat.md`). Skills live in `.agents/skills/` (symlinked from `.claude/skills/`).
- Streamdown ships Tailwind classes and each plugin ships its own dist; `assets/main.css` must keep the `@source "../../../../node_modules/streamdown/dist/*.js"` and `@source ".../@streamdown/{code,cjk}/dist/*.js"` lines (deps are installed in `apps/desktop/node_modules`) or styles silently disappear. Streaming markdown uses `caret` + `isAnimating` (both required) instead of a separate spinner.
